## 1. 서비스 개요

### 서비스명

**OFF:ON (오프온)**

### 한 줄 소개

퇴근 후 남은 에너지와 시간에 맞춰, 오늘의 회복 루틴을 제안하는 AI
플래너.

### 슬로건

**업무는 OFF, 나의 회복은 ON.**

### 배경 및 문제

많은 직장인은 퇴근 후 피로와 선택 부담 때문에 휴식 시간마저 목적 없이
보내곤 한다. OFF:ON은 사용자의 현재 상태와 남은 시간을 간단히 입력받아,
부담 없이 바로 시작할 수 있는 현실적인 저녁 회복 루틴을 제안한다.

### 서비스 목표

사용자가 "오늘 저녁에 무엇을 해야 회복될까?"를 오래 고민하지 않고,
자신의 시간과 에너지에 맞는 작은 회복 루틴을 바로 시작하게 한다.

### 타겟 사용자

-   퇴근 후 피로를 느끼지만 휴식 방법을 정하기 어려운 20\~30대 직장인
-   혼자 사는 생활 속에서 저녁 시간을 더 의식적으로 보내고 싶은 사용자
-   거창한 자기계발보다 현실적으로 실행 가능한 회복 루틴을 원하는 사용자

### 핵심 가치 제안

-   개인의 현재 상태에 맞춘 현실적인 회복 루틴을 제공한다.
-   단계와 예상 시간을 명확히 제시해 선택 부담을 줄인다.
-   생산성이나 성취를 강요하지 않고 하루를 편안하게 마무리하도록 돕는다.
-   다양한 회복 행동을 상황에 맞게 조합한다.

## 2. 핵심 사용자 시나리오

1.  사용자가 퇴근 후 OFF:ON에 접속한다.
2.  홈 화면에서 서비스의 목적을 이해하고 **"오늘의 루틴 만들기"**를
    선택한다.
3.  회복 플래너에서 4단계 질문에 차례로 답한다.
4.  JavaScript가 입력값을 정리하여 `/api/recovery-plan`으로 요청한다.
5.  Vercel Serverless Function(Python)이 Gemini API를 호출해 개인화된
    회복 루틴을 생성한다.
6.  사용자는 결과 카드에서 루틴 제목, 추천 이유, 단계별 시간과 행동,
    실행 팁, 마무리 메시지를 확인한다.
7.  결과가 마음에 들지 않으면 **다시 추천받기**를 선택하거나 **처음부터
    다시 하기**로 입력을 변경한다.

-   데스크톱에서는 상단 메뉴를 통해 각 주요 섹션으로 이동한다.
-   모바일에서는 햄버거 메뉴를 사용한다.
-   **"오늘의 루틴 만들기"** CTA는 회복 플래너 영역으로 이동한다.
-   결과가 생성되면 결과 영역으로 자동 스크롤한다.

## 4. 핵심 기능 명세

### 4.1 오늘의 회복 루틴 만들기

플래너는 한 화면에 한 질문씩 보여주는 4단계 방식으로 구성한다. 사용자는
이전 단계로 돌아가 답변을 수정할 수 있다.

  -----------------------------------------------------------------------
  단계              질문              선택지            활용 방식
  ----------------- ----------------- ----------------- -----------------
  Q1                "지금             예 / 아니오       퇴근 전·후 상황에
                    퇴근했나요?"                        맞춰 루틴의
                                                        맥락을 조정한다.

  Q2                "기분이 어때요?"  😊 좋아요 / 😐    활동의 분위기와
                                      그냥 그래요 / 😔  강도를 조정한다.
                                      별로예요          

  Q3                "많이 지쳤나요?"  😴 완전 방전 / 😐 활동량과 회복
                                      좀 피곤해요 / 💪  중심 정도를
                                      그래도 괜찮아요   결정한다.

  Q4                "저녁 시간은      1시간 이내 /      루틴의 전체 예상
                    얼마나 비어       1\~2시간 / 3시간  시간을 결정한다.
                    있나요?"          이상              
  -----------------------------------------------------------------------

모든 항목은 필수 입력이다.

### 4.2 AI 추천 로직

AI는 다음 요소를 고려해 회복 루틴을 생성한다.

-   현재 기분
-   현재 피로도
-   사용 가능한 저녁 시간
-   퇴근 여부
-   행동의 난이도와 부담 정도
-   서로 다른 유형의 회복 행동 조합

핵심 원칙: 1. 사용자의 상태와 남은 시간을 우선적으로 반영한다. 2. 실제
생활에서 실행할 수 있는 구체적인 행동을 제안한다. 3. 같은 행동이나
비슷한 구성의 반복을 줄인다. 4. 환경 정리, 생활 돌보기, 감각 전환,
가벼운 움직임, 즐거움, 생각 정리 등 다양한 회복 행동을 상황에 맞게
조합한다. 5. 피로도가 높을수록 행동의 난이도와 개수를 낮춘다. 6.
생산성이나 성취를 강요하지 않는다. 7. 의료 진단이나 치료 조언을 하지
않는다.

### 4.3 시간 배분 규칙

-   **1시간 이내:** 전체 30\~60분
-   **1\~2시간:** 전체 60\~100분
-   **3시간 이상:** 전체 90\~150분
-   `완전 방전` 또는 `별로예요`인 경우에는 위 범위보다 짧게 구성할 수
    있다.
-   `3시간 이상`을 선택하더라도 모든 시간을 활동으로 채우지 않고 회복에
    필요한 활동과 여유 시간을 고려한다.

### 4.4 AI 출력

AI는 JSON 형식으로 다음 항목을 반환한다.

  출력 항목           설명
  ------------------- ----------------------------------------------------
  `title`             오늘의 회복 루틴 제목
  `summary`           현재 상태와 루틴 구성에 대한 간단한 설명
  `steps`             3\~5개의 단계. 각 단계는 시간, 행동, 설명으로 구성
  `tip`               루틴을 부담 없이 실행하기 위한 팁
  `closing_message`   하루 마무리를 위한 따뜻한 메시지

``` json
{
  "title": "여유로운 저녁, 나를 돌보는 회복 루틴",
  "summary": "지금의 에너지와 남은 시간을 고려해 생활을 가볍게 정리하고 나만의 시간을 보내는 루틴입니다.",
  "steps": [
    {
      "minutes": 15,
      "action": "환경 리셋",
      "description": "눈에 잘 띄는 공간 한 곳만 가볍게 정리해 보세요."
    },
    {
      "minutes": 30,
      "action": "생활 돌보기",
      "description": "좋아하는 음료나 간단한 식사를 준비하며 천천히 저녁을 보내세요."
    },
    {
      "minutes": 40,
      "action": "즐거움",
      "description": "읽고 싶었던 책이나 좋아하는 영상을 보며 나만의 시간을 가져보세요."
    }
  ],
  "tip": "모든 단계를 완벽하게 할 필요는 없어요. 편안한 단계부터 시작해도 충분합니다.",
  "closing_message": "오늘도 수고 많으셨습니다. 남은 시간은 당신의 평온을 위해 사용해 주세요."
}
```

## 6. 콘텐츠 안전 기준

-   AI는 의료 진단이나 치료 지시를 하지 않는다.
-   AI는 사용자의 상태를 전문적으로 진단하거나 판단하지 않는다.
-   AI 결과는 일상에서 활용할 수 있는 회복 아이디어이며 전문적인
    의료·심리 상담을 대신하지 않는다.
-   사용자를 생산성이나 성취 기준으로 평가하거나 압박하지 않는 표현을
    사용한다.

## 7. 디자인 및 반응형 요구사항

### 디자인 방향

-   키워드: **차분함, 전환, 저녁, 부담 없는 회복**
-   따뜻하고 편안한 저녁 시간의 느낌을 전달한다.
-   크림·베이지 계열 배경과 그린 계열 포인트 컬러를 사용한다.
-   `OFF → ON` 전환 그래픽, 토글 모티프, 둥근 카드와 단계형 결과 UI를
    사용한다.
-   사용자의 상태를 존중하는 부드러운 말투를 사용한다.

### 반응형 기준

  -----------------------------------------------------------------------
  화면                    기준 너비               구현 기준
  ----------------------- ----------------------- -----------------------
  모바일                  375px 이상              한 열 레이아웃,
                                                  터치하기 쉬운 버튼,
                                                  햄버거 메뉴

  태블릿                  768px 이상              카드 간격과 글자 크기
                                                  조정

  데스크톱                1024px 이상             넓은 여백과 카드 기반
                                                  레이아웃 유지
  -----------------------------------------------------------------------

모바일과 데스크톱에서 메뉴, 플래너, 결과 카드, 오류 메시지가 잘리지 않고
읽기 쉬운지 확인한다.

### UX 고도화

#### 다크 모드

- 사용자가 라이트 모드와 다크 모드를 전환할 수 있다.
- 테마 변경 시 기존 콘텐츠와 레이아웃을 유지한다.
- 사용자가 선택한 테마를 브라우저에 저장하여 새로고침 후에도 유지한다.

#### 마이크로 인터랙션

- 선택 버튼의 선택 상태를 시각적으로 피드백한다.
- 버튼의 hover / active 상태를 제공한다.
- AI 결과 카드가 나타날 때 간단한 등장 애니메이션을 적용한다.
- 가이드 카드 등 주요 인터랙션 요소에 가벼운 움직임을 적용한다.
- `prefers-reduced-motion` 설정을 고려한다.

## 8. 기술 설계

### 개발 환경

-   프론트엔드: 순수 HTML / CSS / JavaScript
-   백엔드: Vercel Serverless Functions (Python)
-   AI: Google Gemini API
-   배포: Vercel
-   저장소: GitHub

### 프로젝트 구조

``` text
off-on/
├─ index.html
├─ css/
│  └─ style.css
├─ js/
│  └─ app.js
├─ api/
│  └─ recovery-plan.py
├─ outputs/
├─ requirements.txt
├─ README.md
├─ .gitignore
└─ vercel.json
```

### 프론트엔드 역할

-   **HTML:** 화면의 구조와 콘텐츠를 구성한다.
-   **CSS:** 레이아웃, 색상, 타이포그래피, 카드, 반응형 화면을 구현한다.
-   **JavaScript:** 질문 단계 이동, 입력값 검증, API 요청, 로딩·오류
    상태, AI 응답 렌더링을 담당한다.

### 백엔드/API 역할

``` text
사용자
  ↓
HTML / CSS / JavaScript
  ↓
JavaScript fetch()
  ↓
POST /api/recovery-plan
  ↓
Vercel Serverless Function
  ↓
Gemini API
  ↓
JSON 응답
  ↓
JavaScript가 결과 카드에 표시
```

### API 엔드포인트

``` text
POST /api/recovery-plan
```

요청 본문:

``` json
{
  "isOffWork": true,
  "mood": "별로예요",
  "fatigue": "완전 방전",
  "availableTime": "1시간 이내"
}
```

### 환경 변수 및 보안

-   API 키: `GEMINI_API_KEY`
-   선택적 모델 설정: `GEMINI_MODEL`
-   실제 API 키는 코드에 직접 작성하지 않는다.
-   Vercel 배포 환경에서는 Environment Variables로 관리한다.
-   API 키는 HTML, JavaScript, README, 스크린샷, GitHub 코드 및 커밋에
    노출하지 않는다.
-   프론트엔드는 Gemini API를 직접 호출하지 않고 `/api/recovery-plan`을
    통해 백엔드에 요청한다.

### 의존성

`requirements.txt`에서 Gemini API 호출에 필요한 `google-genai` 패키지를
관리한다.

## 9. 비기능 요구사항

-   프론트엔드는 AI 요청에 대해 최대 45초까지 응답을 기다린다.
-   API 오류가 발생해도 페이지 전체가 깨지지 않아야 한다.
-   모바일과 데스크톱에서 콘텐츠가 잘리지 않고 읽기 쉬워야 한다.
-   API 키 등 민감한 정보가 클라이언트 코드에 노출되지 않아야 한다.
-   선택 상태와 오류 상태는 색상만으로 구분하지 않는다.
-   버튼과 입력 요소는 키보드로 사용할 수 있도록 구성한다.

### 주요 개선 검증 사례

#### 시간 배분 개선

초기 AI 결과에서 `3시간 이상`을 선택했음에도 전체 루틴이 지나치게 짧게
생성되는 문제가 발견되었다. 이에 따라 AI 프롬프트에 사용 가능한 시간별
목표 범위를 명시하고, `3시간 이상`의 경우 90\~150분을 우선하도록
개선하였다.

#### 추천 루틴 다양화

초기 결과에서 샤워, 음악 감상 등 유사한 행동이 반복되는 문제가
발견되었다. 이에 따라 다양한 회복 행동을 상황에 맞게 조합하도록
프롬프트를 개선하였다.
