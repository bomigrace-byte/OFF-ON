# OFF:ON(오프온) 제품 요구사항 문서

> 버전 1.0 · 작성일 2026-08-31

## 1. 서비스 개요

### 서비스명

**OFF:ON (오프온)**

### 한 줄 소개

퇴근 후 남은 에너지와 시간에 맞춰, 오늘의 회복 루틴을 제안하는 AI 플래너.

### 슬로건

**업무는 OFF, 나의 회복은 ON.**

### 배경 및 문제

많은 직장인은 퇴근 후 피로와 선택 부담 때문에 휴식 시간마저 목적 없이 보내곤 한다. 충분히 쉬지 못하면 다음 날의 컨디션과 만족도에도 영향을 준다. 오프온은 사용자의 현재 상태를 간단히 입력받아, 부담 없이 바로 시작할 수 있는 저녁 회복 행동을 제안한다.

### 서비스 목표

사용자가 “오늘 저녁에 무엇을 해야 회복될까?”를 오래 고민하지 않고, 자신의 시간과 에너지에 맞는 작은 회복 루틴을 시작하게 한다.

### 타겟 사용자

- 퇴근 후 피로를 느끼지만 휴식 방법을 정하기 어려운 20~30대 직장인
- 혼자 사는 생활 속에서 저녁 시간을 더 의식적으로 보내고 싶은 사용자
- 거창한 자기계발보다 현실적으로 실행 가능한 루틴을 원하는 사용자

### 핵심 가치 제안

- 개인의 상태에 맞춘 짧고 실현 가능한 회복 루틴을 제공한다.
- 사용자가 선택 피로 없이 바로 행동할 수 있도록 단계와 시간을 명확히 제시한다.
- 하루를 죄책감 없이 마무리하도록 따뜻하고 비판단적인 메시지를 제공한다.

## 2. 핵심 사용자 시나리오

1. 사용자가 퇴근 후 오프온에 접속한다.
2. 홈 화면에서 서비스의 목적을 이해하고 “오늘의 루틴 만들기”를 선택한다.
3. 4단계 질문(퇴근 여부, 현재 기분, 피로도, 남은 시간)에 답한다.
4. 프론트엔드가 `/api/recovery-plan`으로 입력값을 전송한다.
5. Python Serverless Function이 AI API를 호출해 개인화된 회복 루틴을 생성한다.
6. 사용자는 루틴 카드에서 순서, 예상 시간, 오늘의 한마디를 확인한다.
7. 마음에 드는 루틴을 실천하거나 입력을 바꿔 다시 추천받는다.

## 3. 정보 구조 및 페이지 구성

최소 3개 섹션을 상단 메뉴로 이동할 수 있게 구성한다. 단일 페이지 앵커 이동 또는 개별 HTML 페이지 모두 가능하다.

| 메뉴/섹션 | 목적 | 주요 구성 |
| --- | --- | --- |
| 홈 (Home) | 서비스 가치 전달 및 기능 진입 | OFF→ON 히어로, 슬로건, 루틴 만들기 CTA, 이용 흐름 3단계 |
| 회복 플래너 (Planner) | AI 추천 제공 | 4단계 질문형 입력, 진행 표시, 생성 버튼, 로딩 상태, 회복 루틴 결과 카드, 재추천 버튼 |
| 회복 가이드 (Guide) | 회복 방법 이해 및 신뢰 형성 | 짧은 회복 팁, 시간별 회복 예시, 이용 주의사항 |
| FAQ | 사용자의 질문 해소 | AI 추천 기준, 개인정보·API 관련 안내, 오류 발생 시 안내 |

### 네비게이션

- 데스크톱: 상단 고정 메뉴에서 각 섹션으로 부드럽게 이동한다.
- 모바일: 햄버거 메뉴 또는 펼침형 메뉴를 제공한다.
- 모든 화면에서 “오늘의 루틴 만들기” 버튼은 플래너 섹션으로 이동한다.

## 4. 핵심 기능 명세

### 4.1 오늘의 회복 루틴 만들기

#### 입력 및 질문 흐름

플래너는 한 번에 많은 선택지를 보이지 않도록, 한 화면에 한 질문씩 보여 주는 4단계 방식으로 구성한다. 상단에는 `1 / 4` 형식의 진행 표시를 제공하고, 각 답변을 선택하면 “다음” 버튼으로 이동한다. 이전 단계로 돌아가 답변을 수정할 수 있다.

| 단계 | 질문 | UI/선택지 | 활용 방식 |
| --- | --- | --- | --- |
| Q1 | “지금 퇴근했나요?” | 예 / 아니오 | 아니오일 때는 퇴근 전에도 가능한 짧은 전환 루틴으로 안내한다. 서비스 이용을 막지 않는다. |
| Q2 | “기분이 어때요?” | 😊 좋아요 / 😐 그냥 그래요 / 😔 별로예요 | 루틴의 말투와 활동 강도를 조정한다. |
| Q3 | “많이 지쳤나요?” | 😴 완전 방전 / 😐 좀 피곤해요 / 💪 그래도 괜찮아요 | 루틴의 총 활동량과 휴식 비중을 결정한다. |
| Q4 | “저녁 시간은 얼마나 비어 있나요?” | 1시간 이내 / 1~2시간 / 3시간 이상 | 전체 루틴의 예상 시간을 결정한다. |

선택 항목은 모두 필수다. 단, AI 결과를 더 개인화하고 싶은 사용자를 위해 마지막 단계 아래에 선택형 “지금 가장 필요한 것” 항목(조용히 쉬기, 몸 풀기, 가벼운 즐거움, 정리하기)과 최대 200자의 추가 설명을 제공할 수 있다.

#### AI 출력

AI는 다음 항목을 JSON 형태로 반환하고, 화면은 이를 카드 형태로 표시한다.

| 출력 항목 | 설명 |
| --- | --- |
| `title` | 오늘의 회복 루틴 제목. 예: “30분 가벼운 리셋” |
| `summary` | 현재 상태에 맞는 추천 이유 1~2문장 |
| `steps` | 시간, 행동, 짧은 설명을 포함한 3~5개 단계 |
| `tip` | 부담을 줄이는 실행 팁 1개 |
| `closing_message` | 하루 마무리를 위한 따뜻한 한마디 |

#### 화면 예시

```text
오늘의 회복 루틴: 30분 가벼운 리셋

지금은 무리해서 생산적인 일을 하기보다, 몸과 생각의 긴장을 낮추는 시간이 필요해요.

01 · 5분  물 한 잔을 마시고 창문을 열어 환기하기
02 · 10분 가벼운 샤워 또는 목·어깨 스트레칭
03 · 10분 좋아하는 음악과 함께 간단한 저녁 준비하기
04 · 5분  내일 할 일 한 가지만 적고 화면 끄기

실행 팁: 첫 단계만 시작해도 오늘의 루틴은 충분합니다.
오늘의 한마디: “더 잘 해내는 것보다, 에너지를 되찾는 일이 먼저예요.”
```

### 4.2 UX 상태 및 실패 처리

| 상황 | 처리 방식 | 사용자 안내 문구 |
| --- | --- | --- |
| 필수값 누락 | 생성 요청을 막고 해당 영역 강조 | “오늘의 상태를 모두 선택해 주세요.” |
| 입력 글자 수 초과 | 200자 입력 제한 및 글자 수 표시 | “추가 설명은 200자 이내로 작성해 주세요.” |
| 요청 진행 중 | 생성 버튼 비활성화, 로딩 애니메이션 표시 | “AI가 오늘의 회복 시간을 설계하고 있어요…” |
| API 오류(4xx/5xx) | 오류 영역과 재시도 버튼 표시 | “루틴을 불러오지 못했어요. 잠시 후 다시 시도해 주세요.” |
| 응답 지연/타임아웃 | 약 15초 후 요청 취소 및 재시도 제공 | “응답이 늦어지고 있어요. 잠시 후 다시 시도해 주세요.” |
| 예상하지 못한 응답 | 기본 오류 메시지와 재시도 제공 | “일시적인 문제가 발생했어요. 다시 시도해 주세요.” |

### 4.3 콘텐츠 안전 기준

- AI는 의료 진단, 치료 지시, 정신건강 진단을 하지 않는다.
- 자해·위기 관련 입력이 있으면 전문 기관 또는 신뢰할 수 있는 주변인에게 도움을 요청하라는 안전 안내를 우선 표시한다.
- AI 결과는 일상적인 회복 아이디어이며 전문적 의료 조언이 아니라는 문구를 가이드와 결과 하단에 표시한다.

## 5. 디자인 및 반응형 요구사항

### 디자인 방향

- 키워드: 차분함, 전환, 저녁, 부담 없는 회복
- 색상: 다크 네이비를 기본으로 하고 코랄 또는 라임을 포인트로 사용한다.
- 주요 시각 요소: `OFF → ON` 전환 그래픽, 토글 모티프, 둥근 루틴 카드
- 문체: 명령하거나 평가하지 않고, 사용자의 상태를 존중하는 부드러운 말투를 쓴다.

### 반응형 기준

| 화면 | 기준 너비 | 구현 기준 |
| --- | --- | --- |
| 모바일 | 375px 이상 | 한 열 레이아웃, 터치하기 쉬운 버튼, 메뉴 축소 |
| 태블릿 | 768px 이상 | 카드 간격과 글자 크기 조정 |
| 데스크톱 | 1024px 이상 | 플래너 입력 영역과 결과 영역을 2열로 배치 가능 |

모바일과 데스크톱에서 메뉴, 폼, 결과 카드, 오류 메시지가 잘리지 않고 읽기 쉬운지 직접 확인한다.

## 6. 기술 설계

### 프로젝트 구조

```text
offon/
├─ index.html
├─ css/
│  └─ style.css
├─ js/
│  └─ app.js
├─ api/
│  └─ recovery_plan.py
├─ images/
├─ requirements.txt
├─ README.md
├─ .gitignore
└─ vercel.json
```

### 프론트엔드

- HTML: 섹션 구조, 폼, 버튼, 결과 카드의 의미 있는 구조를 작성한다.
- CSS: 레이아웃, 색상, 카드, 반응형 미디어 쿼리, 로딩 상태를 구현한다.
- JavaScript: 입력값 검증, 로딩/오류 상태 제어, `fetch()` 요청, AI 응답 렌더링을 담당한다.

### 백엔드/API

- Vercel Serverless Function은 `api/recovery_plan.py`에 구현한다.
- `POST /api/recovery-plan` 요청에서 JSON 입력을 받는다.
- Python이 AI API를 호출하고 필요한 결과만 JSON으로 반환한다.
- 패키지 의존성은 `requirements.txt`에 명시한다.

#### 요청 예시

```json
{
  "isOffWork": true,
  "mood": "별로예요",
  "fatigue": "완전 방전",
  "availableTime": "1시간 이내",
  "preferences": ["조용히 쉬기"],
  "note": "하루 종일 회의가 많았어요."
}
```

#### 성공 응답 예시

```json
{
  "title": "30분 조용한 리셋",
  "summary": "회의로 쌓인 자극을 줄이고, 몸의 긴장을 천천히 낮추는 루틴이에요.",
  "steps": [
    {"minutes": 5, "action": "알림을 끄고 물 한 잔 마시기", "description": "업무 모드에서 잠시 빠져나와요."},
    {"minutes": 15, "action": "따뜻한 샤워하기", "description": "몸의 긴장을 낮춰 보세요."},
    {"minutes": 10, "action": "조명 아래에서 좋아하는 음악 듣기", "description": "아무것도 하지 않는 시간도 회복입니다."}
  ],
  "tip": "완벽히 따라 하지 않아도 첫 단계만 하면 충분해요.",
  "closing_message": "오늘은 잘 버틴 나를 쉬게 해 주세요."
}
```

### 환경 변수 및 보안

- 환경 변수명: `OPENAI_API_KEY` (선택한 AI 제공자에 맞게 변경 가능)
- 로컬에서는 `.env`에 저장하고 `.gitignore`에 포함한다.
- Vercel 대시보드의 Environment Variables에도 동일한 키를 설정한다.
- API 키를 HTML, JavaScript, README 예시, 스크린샷, GitHub 커밋에 절대 노출하지 않는다.
- 프론트엔드는 AI 제공자 API를 직접 호출하지 않고 반드시 `/api/recovery-plan`만 호출한다.

## 7. 비기능 요구사항

- 결과는 요청 후 가능한 15초 안에 표시한다.
- 버튼, 입력 요소, 오류 메시지는 키보드로도 접근 가능해야 한다.
- 색상만으로 오류/선택 상태를 구분하지 않고 텍스트를 함께 제공한다.
- API 오류가 발생해도 페이지 전체가 깨지지 않아야 한다.
- 같은 버튼을 여러 번 눌러 중복 요청이 발생하지 않도록 로딩 중 버튼을 비활성화한다.

| TC-07 | 모바일 | 375px 너비 | 메뉴, 폼, 결과가 한 열로 정상 표시된다. |
| TC-08 | 데스크톱 | 1440px 너비 | 섹션과 카드가 여백을 유지하며 정상 표시된다. |
| TC-09 | 배포 검증 | Vercel URL 접속 | 메뉴 이동과 AI 결과 생성이 배포 환경에서도 동작한다. |
