## 1. 서비스 한눈에 보기

### 서비스명
**OFF:ON (오프온)**

### 슬로건
**업무는 OFF, 나의 회복은 ON.**

### 한 줄 소개
**퇴근 후 남은 에너지와 시간에 맞춰, 오늘의 회복 루틴을 제안하는 AI 플래너**

### 서비스 목적

퇴근 후에는 쉬고 싶어도 “오늘 저녁에 뭘 하지?”를 결정하는 것 자체가 부담이 될 수 있다.

OFF:ON은 사용자가 자신의 현재 기분, 피로도, 퇴근 여부와 남은 시간을 간단하게 입력하면 **지금의 상태에서 실제로 실행할 수 있는 회복 루틴**을 AI가 제안해 주는 서비스다.

핵심은 더 많은 일을 하게 만드는 것이 아니라, **하루의 남은 시간을 부담 없이 자신에게 돌려주는 것**이다.

---

## 2. 문제 정의

### 사용자가 겪는 문제

- 퇴근 후 너무 지쳐 무엇을 할지 결정하기 어렵다.
- 쉬고 싶지만 막상 쉬는 방법을 정하지 못하고 시간을 보낸다.
- 일반적인 자기계발 루틴은 피곤한 날에도 해야 할 일이 많게 느껴질 수 있다.
- 같은 휴식 행동만 반복하다 보니 실제로 회복되는 느낌이 부족할 수 있다.

### 해결 방향

OFF:ON은 사용자가 긴 설명을 작성하지 않아도 되도록 4개의 간단한 질문만 제공한다.

그리고 AI가 입력된 상태와 시간에 맞춰 **짧고 구체적인 행동들을 하나의 저녁 루틴으로 조합**한다.

## 3. 타겟 사용자

### 핵심 타겟

**퇴근 후 피로를 느끼지만 저녁 시간을 어떻게 보내야 할지 결정하기 어려운 20~30대 직장인**

### 주요 사용자 특성

- 업무가 끝난 뒤 혼자 보내는 저녁 시간이 있다.
- 자기계발이나 생산성보다 편안한 회복을 원하는 날이 있다.
- 긴 계획을 세우기보다 지금 바로 실행할 수 있는 간단한 제안을 선호한다.
- 현재 컨디션에 따라 필요한 휴식 방식이 달라진다.

## 4. 핵심 가치

### ① 선택 부담 감소

사용자가 직접 수많은 휴식 방법을 검색하거나 계획하지 않아도 된다.

### ② 현재 상태 기반 추천

기분과 피로도, 남은 시간을 고려해 그날에 맞는 루틴을 제안한다.

### ③ 현실적인 실행 가능성

“푹 쉬세요”처럼 추상적인 조언 대신 실제로 할 수 있는 행동과 시간을 제시한다.

### ④ 부담 없는 회복

생산성이나 성취를 요구하지 않고, 사용자가 편안하게 하루를 마무리하는 것을 돕는다.

### ⑤ 다양한 회복 경험

환경 정리, 생활 돌보기, 감각 전환, 가벼운 움직임, 즐거움, 생각 정리 등 다양한 유형의 행동을 상황에 맞게 조합한다.

## 5. 서비스 구성

OFF:ON은 하나의 웹페이지에서 메뉴를 통해 주요 섹션으로 이동하는 구조다.

| 섹션 | 역할 | 주요 내용 |
|---|---|---|
| **홈** | 서비스 소개 및 진입 | 서비스 메시지, OFF→ON 콘셉트, CTA, 이용 방법 |
| **회복 플래너** | 사용자 입력 및 AI 추천 | 4단계 질문, 진행률, AI 루틴 생성 |
| **회복 결과** | AI 결과 확인 | 루틴 제목, 추천 이유, 단계별 시간·행동, 팁, 마무리 메시지 |
| **회복 가이드** | 서비스 이해 및 회복 정보 | 회복에 대한 짧은 안내와 가이드 |

※ 실제 구현은 홈 / 회복 플래너 / 회복 가이드 메뉴를 중심으로 구성되며, AI 결과는 플래너 이후 결과 영역에 표시된다.

## 7. AI 기능 설계

### AI 기능명

**오늘의 회복 루틴 AI**

### AI가 해결하는 문제

사용자의 현재 상태에 따라 **오늘 저녁에 실행할 수 있는 회복 행동을 선택하고 순서와 시간을 구성하는 것**이다.

### AI 입력

사용자는 다음 4가지 정보를 입력한다.

| 입력 | 선택지 | AI 활용 |
|---|---|---|
| 퇴근 여부 | 예 / 아니오 | 현재 상황과 루틴의 맥락 조정 |
| 기분 | 좋아요 / 그냥 그래요 / 별로예요 | 활동 분위기와 강도 조정 |
| 피로도 | 완전 방전 / 좀 피곤해요 / 그래도 괜찮아요 | 활동량과 난이도 조정 |
| 남은 시간 | 1시간 이내 / 1~2시간 / 3시간 이상 | 루틴 전체 시간 구성 |

### AI 출력

AI는 다음 정보를 JSON으로 생성한다.

- **루틴 제목**
- **루틴 추천 이유**
- **3~5개의 회복 단계**
  - 예상 시간
  - 행동
  - 구체적인 설명
- **실행 팁**
- **마무리 메시지**

### 예시

**입력**

> 퇴근함 / 기분이 별로예요 / 완전 방전 / 1시간 이내

**출력 예시**

> **여유로운 저녁, 나를 돌보는 회복 루틴**
>
> 01 · 15분 — 환경 리셋  
> 눈에 잘 띄는 공간 한 곳만 가볍게 정리하기
>
> 02 · 20분 — 생활 돌보기  
> 간단한 식사와 음료를 준비하며 천천히 저녁 보내기
>
> 03 · 15분 — 즐거움  
> 좋아하는 콘텐츠를 보며 나만의 시간 보내기

## 8. AI 추천 원칙

AI가 단순히 휴식 행동을 랜덤으로 나열하지 않도록 다음 원칙을 적용한다.

1. 사용자의 현재 기분과 피로도를 가장 우선적으로 반영한다.
2. 사용 가능한 시간을 고려해 루틴의 길이를 조정한다.
3. 피로도가 높으면 행동의 난이도와 개수를 낮춘다.
4. 같은 행동이나 비슷한 루틴의 반복을 줄인다.
5. 서로 다른 유형의 회복 행동을 상황에 맞게 조합한다.
6. 모든 행동은 일상에서 실제로 실행할 수 있도록 구체적으로 작성한다.
7. 생산성이나 성취를 강요하지 않는다.
8. 의료 진단이나 치료 조언을 하지 않는다.

### 시간 배분 기준

- **1시간 이내:** 30~60분
- **1~2시간:** 60~100분
- **3시간 이상:** 90~150분
- 단, 완전 방전 또는 기분이 별로인 경우에는 더 짧게 구성할 수 있다.

## 9. UX 및 실패 처리

사용자가 오류 상황에서도 서비스를 계속 사용할 수 있도록 기본적인 상태 처리를 제공한다.

### 필수값 누락

질문에 답하지 않고 다음 단계로 이동하려 하면:

> **“가장 가까운 답을 하나 골라주세요.”**

라는 안내를 표시하고 이동을 막는다.

### AI 생성 중

AI 요청 중에는 로딩 화면을 표시한다.

> **“AI가 오늘의 회복 시간을 설계하고 있어요…”**

### API 오류

AI API 또는 서버에서 오류가 발생하면 결과 대신 오류 안내와 **다시 시도하기** 버튼을 제공한다.

### 요청 지연

프론트엔드에서는 최대 45초까지 응답을 기다리며, 응답이 없으면 요청을 취소하고 오류 상태로 전환한다.

## 12. 보안 및 운영 기준

- Gemini API 키는 `GEMINI_API_KEY` 환경 변수로 관리한다.
- 선택적으로 `GEMINI_MODEL` 환경 변수를 사용할 수 있다.
- API 키를 프론트엔드 코드에 노출하지 않는다.
- API 키를 GitHub, README, 스크린샷 등에 포함하지 않는다.
- 프론트엔드가 Gemini API를 직접 호출하지 않고 Python 백엔드를 통해 요청한다.
- AI API 오류 발생 시 사용자에게 재시도 방법을 제공한다.

## 14. 테스트 및 개선

### 기본 테스트

- 정상 입력 → AI 결과 생성
- 필수값 미선택 → 입력 오류 안내
- API 오류 → 오류 안내 및 재시도
- 모바일 화면 → 레이아웃 확인
- 데스크톱 화면 → 레이아웃 확인
- 배포 URL → 전체 기능 확인

### AI 결과 개선 사례

#### ① 시간 배분 문제 개선

초기 테스트에서 `3시간 이상`을 선택했는데도 약 40분 정도의 짧은 루틴이 생성되는 문제가 발견되었다.

이를 해결하기 위해 AI 프롬프트에 사용 가능한 시간별 목표 범위를 명시하고, `3시간 이상`에서는 90~150분의 루틴을 우선하도록 개선했다.

#### ② 추천 행동 다양성 개선

초기 테스트에서 샤워, 음악 감상 등 비슷한 회복 행동이 반복되는 문제가 발견되었다.

이를 해결하기 위해 다양한 회복 행동 카테고리를 정의하고, 사용자의 상태에 따라 서로 다른 유형의 행동을 조합하도록 AI 프롬프트를 개선했다.

### 개선의 핵심

OFF:ON의 AI 기능은 처음부터 완벽한 답을 생성하는 것보다,

**AI 결과 확인 → 문제 발견 → 원인 분석 → 프롬프트 개선 → 다시 테스트**

의 과정을 통해 추천 품질을 높이는 방향으로 설계했다.
